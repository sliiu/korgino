# 服务行点击逻辑统一 + 对话面板可拖拽改高（2026-11-01）

范围：设置「翻译服务」里各服务行的点击逻辑，以及对话面板的高度拖拽。grill 过三条，结论如下。

## 背景：两套服务行

设置里「有密钥字段的服务行」现在有两套写法：

- **静态行**（内置翻译引擎、OCR、词典）：名字放在 `Toggle` 的 label 里，点名字 = 切勾选 + 自动展开；另有一个独立 chevron 管展开。
- **动态行**（AI、识别 ASR、朗读 TTS，都是用户自己加的预设）：勾选框只切勾选；名字是独立 `Button`，点名字只展开；再加 chevron。

用户要的是把静态行收到动态行（AI）那套：勾选只走勾选框，点名字只展开。

## 决定（2026-11-01）

- **Q1 统一范围**：内置翻译引擎 + OCR 一起改成 AI 那套——勾选框只切勾选；点名字/图标展开；chevron 也展开；展开与「是否启用」解耦（没启用也能展开填 key，跟 AI 一致）。词典行保持「勾选框 + 名字」、不加展开（常态没有可展开内容，映射引擎未启用时才顺带显示字段，维持原样）。
- **Q2 启用时自动展开**：保留「缺 key 时才自动展开」——已配好的引擎启用时不弹开，缺 key 的启用时自动展开编辑区方便贴 key。这不违背「勾选仅点勾选框」：勾选框仍只切勾选，自动展开只是启用时的一次性便利。
- **Q3 对话面板拖拽改高**：两个载体都处理。
  - 翻译文件窗口：译文区与对话面板之间改用 `HSplitView`/`VSplitView`，对话面板从写死的 300 改成带 min/ideal/max 的可拖范围。
  - 浮动翻译浮层：已有 `PanelEdgeResize`，顶/底命中带太细（5px/10px），加宽让边更好抓；确认 chat 展开时高度能拖。

## 不动

- 动态行（AI/ASR/TTS）已经是目标形态，不改。
