# 一份安装包，15 和 26 都能开

## 结论

发布只打一份。`./build.sh --release` 产出 `dist/Korgino.app`，最低系统仍是 `Info.plist` 里的 15.0，不再按系统版本改写。推送 `v*` 标签后流水线只建一个磁盘镜像 `Korgino-<version>.dmg`。

`--macos15` 和 `--macos26` 不再接受，跑它们会报错并指向 `--release`。本机 `./build.sh` 不带参数仍是开发包，行为不变。

## 为什么

两份包的二进制从来就是同一份：部署目标都是 `macosx15.0`，宏都是 `KORGI_TEST_PRO`，架构都是 arm64 + x86_64。macOS 26 的 API 用 `#available(macOS 26.0, *)` 隔开，15 上编得过、跑得到。唯一的差别是 `--macos26` 把 `LSMinimumSystemVersion` 改成 26.0，15 因此打不开。

拆包的理由在 `0069`：菜单栏应用的 `LSUIElement` 写进 plist，26 上 `open` 报 -600；不写，15 上菜单栏图标出不来。`0072` 改成常规应用之后这个键不再写，拆包没有东西可拆。

15 上「常规应用 + 菜单栏图标」按 `0072` 还没实机看过。合成一份解决不了这一条。

## 考虑过

- 保留两个参数但打出相同的包：发布页仍然要人选一份，而两份没有差别。
- 最低系统提到 26：15 上的人打不开。源码已经照顾 15，没有理由把他们排除。
