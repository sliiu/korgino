# 快捷翻译改成连按三下空格，不再猜输入法

取代 0022 里“连按两下空格”和“输入法组字时那下空格不算”两条。0022 其余部分（读哪一段、怎么写回、进历史）照旧。

## 结论

默认触发是连按三下空格。每一下都算，输入法选词上屏的那一下也算：中文是“选词那下空格 + 再按两下”，英文是“连按三下”。不再判断输入法是不是在组字。

相邻两下之间不超过系统双击间隔，至少 0.6 秒。按住不放的自动重复不算。

只有焦点输入框里已经有划选时，空格才先不放进去，免得划选被一格空格冲掉；没等到第三下，就把扣下的空格按原样补回去。其余情况每一下空格都立刻送进输入框，第三下才吞掉并开始翻译，翻译前把前两下打进去的空格从原文里去掉。

听键盘的监听跑在自己的线程上，回调里只数空格，不碰辅助功能，也不等主线程。问输入框放在另一条后台队列上。

读不到焦点输入框时，给这个应用打开一次辅助功能树再读：Electron 用 `AXManualAccessibility`，不认这个开关的（Chromium、Firefox 系）用 `AXEnhancedUserInterface`。每个进程只开一次。刚启动的 Chromium 要两秒左右才交出焦点，打开后三秒内读不到就接着等，不当成“找不到输入框”。

“不用快捷翻译的应用”是一张名单，默认放终端和代码编辑器。名单里的应用，三下空格照常是空格，组合键也不触发。设置里可以增删，也可以恢复默认。

翻译进行时，划选或输入框上叠一层扫光描边，角上挂“翻译中 · 供应商”。换好时描边闪一下淡出；没换时标签变红，写明原因，停 1.5 秒。拿不到文字位置时，标签挂在焦点窗口上沿。

## 网页编辑区

X 回复框、Thunderbird 写信、Gmail 这类网页编辑区，焦点常落在编辑区里的某一段上。读和写都对着整个编辑区（`AXHighestEditableAncestor`），不对着那一段。

正文先读 `AXValue`。Gecko 的编辑区 `AXValue` 永远是空的，这时用文本标记读：先问这个元素自己的范围（`AXTextMarkerRangeForUIElement`），只有它本身是网页根（`AXWebArea`）才用整页的起止标记。Chromium 的起止标记盖住整页，用在别的元素上会把页面上的字一起读进来。不可编辑的元素一律不用文本标记，焦点停在普通网页上就是“找不到输入框”。

写回之后网页编辑区要过一会儿才读得到新字。写完连续读几次：成了译文算成；一直是原文才换下一种写法；成了别的样子说明已经写进去了，不再写第二遍，免得出现两遍译文。

Chromium 写 `AXSelectedText` 回成功，其实什么都不改。整段替换直接写 `AXValue`；只换划选那一段走“复制确认、再粘贴”。整段换完 Chromium 把光标留在开头，要挪到译文末尾。

从 HID 层发带 ⌘ 的按键（复制、粘贴、全选），系统会一直当 ⌘ 按着，之后的点击和按键都带上 ⌘，直到用户自己按一下 ⌘。用户本来没按 ⌘ 时，发完要补一个 ⌘ 松开。

实测（2026-10-28）：ego lite 里的 X 回复弹窗和帖子下的回复框、冷启动的 Edge、Thunderbird 写信，整段和划选都换成了译文，光标在末尾。ego 的代理窗口在代理控制时不把键盘焦点交给网页，也不响应模拟的 ⌘C，测试时要先交还控制。

## 为什么

用户在 Opera、Cursor、Thunderbird 里试，日志里几乎全是“读不到输入框”：Chromium 和 Electron 默认不把焦点交给辅助功能，问焦点直接返回“没有值”（-25212）；给 Opera 设一次 `AXEnhancedUserInterface` 之后就读得到了。

输入法选词卡住有两个来源。一是监听挂在主线程上，主线程每 0.15 秒去问一次“在不在组字”，问的时候所有按键都要排队。二是 Opera 这类应用答不出组字状态，选词那下空格被当成手势第一下吞掉，读完输入框才补回去；读不到内容的输入框里，空格还要扣 0.8 秒。

靠按键去猜组字（刚打过字母、输入法开着）在输入法的英文模式下会猜错。改成三下之后，组字那下空格正好算第一下，不用猜，也就不用为了猜而扣住空格。

## 考虑过

- 两下空格加按键推断组字。英文模式下猜错，要按三下，规则说不清。
- 只靠辅助功能读组字状态。Opera、Cursor 读不到，选词照样被拖住。
- 中文输入法开着时双空格不触发。中文用户就用不上默认手势。
- 一直替所有应用打开辅助功能树。Chromium 会多建一棵树、多占内存；只在读不到时开。
- 只加字数上限防误触。终端和编辑器里连按空格缩进很常见，“整段”是整个文件或整屏输出，按应用排除更直接。
