# 应用单独一页，三种触发各配一家

快捷翻译、划词和按住 Fn 之前只共用一条应用规则：一个供应商、一种目标语言，而且供应商只有快捷翻译那条路真的读。设置里也只有「快捷翻译」一页，应用规则和排除名单两张表并排摆着。

现在每个来源应用是一条 `QuickAppRule`：划词、快捷翻译、按住 Fn 各存一家（`QuickAppTarget`，含模型），再加语音模式、目标语言和划词插件表。设置里单独一页「应用」，一个应用一张卡，收起时只有名字和状态，展开是「开关」「默认提供商」「其他」三组。

开关是三条，不是一条：划词、快捷翻译、语音各一个，谁也不连累谁。三条各记一份排除名单（`selectExcludedApps` / `quickExcludedApps` / `voiceExcludedApps`，都是 bundle id 数组）。划词插件跟着划词的开关走。敲空格那条路要靠名单同步过滤，所以快捷翻译仍然直接读 `quickExcludedApps`，`AppTrigger` 只是把三份名单收成一个查询口（`isAppOn` / `setAppOn`）。划词、语音两份默认是空的，即默认全开；快捷翻译的默认是终端和代码编辑器，因为连按空格在那里是缩进。规则里全空的应用也留着，表示「开着，但都跟随默认」。

模型只对 AI 那一家有意义，跟着供应商走：换供应商时清掉，供应商被停用或不在目录里时整条应用规则作废，退回这一功能的默认。这跟浮层里当次换模型不同（`0053`），它写回设置。

划词原来跑默认那几家（免费最多两家），应用指定一家并还在目录里时只跑这一家。按住 Fn 原来不看应用，现在先按来源应用定模式和那一家。剪贴板和截图没有来源应用，仍只有全局默认。

默认名单里的应用（终端、代码编辑器）和其它应用一样列在同一张表里，只是默认处于「快捷翻译关」。没有「恢复默认名单」：要开就自己打开，要移出就点减号，减号会把三份名单一起清掉。

划词插件三态：留空跟随插件页的勾选，`none` 这个应用里不弹，`custom` 只弹 `pluginIDs` 里那几个。

旧数据只有一个 `providerID`，解码时落到快捷翻译那一格，其余留空。

## 考虑过

- 三条开关共用一个：终端里连按空格确实要关，但划词和按住 Fn 在那里是要用的，一个开关会顺手把它们也关掉。
- 开关存进 `QuickAppRule` 里：要和排除名单同步，敲空格那条路会读到两份不一致的真相。现在开关就是名单本身，`AppTrigger` 只负责按名字挑一份。
- 每个应用一张独立窗口：设置里已经有左栏，一页一张卡就够，还能一眼看出哪些应用被关着。
- 模型跟着设置走、不按应用存：同一个应用里换供应商常常就是为了换模型，分开存不了这件事。
- 规则里全空就删掉这条：删掉之后卡片会缩回「没配置」的样子，用户看不出这个应用是开着的。
- 保留 `quickAppHidden`：它只是为了记住「用户从默认名单里移出了哪个」，现在默认名单只是默认的开关状态，移出就不该再回来，不需要另记一份。
