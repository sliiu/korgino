# 对话输入的回车先留给输入法

回车把这段话发出去。Shift+回车换行。⌘↩ 也发送。

正在组字时按回车是在上屏选词，不发送。组字结束之后再按回车，才发送。组字从 `setMarkedText` 开始，到 `unmarkText` 结束。回车进来时如果标记文本还在，这一次交给输入法。

释义的搜索框不在这次里。那里的回车就是查询。

## 考虑过

- Option+回车换行：这是 SwiftUI 多行文本框的习惯。Cursor、Grok Bot、ChatGPT 的对话框用的是 Shift+回车。
- 在 SwiftUI `onSubmit` 里看 `hasMarkedText()`：上屏那次回车到达提交时，标记文本已经清掉，拦不住。
- 用全局按键监视去挡回车：对话以外的输入也会撞上，提交仍然发生在组字结束之后。
- 组字期间的回车改成插入换行：上屏会多出一行空行。
