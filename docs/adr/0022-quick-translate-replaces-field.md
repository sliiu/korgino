# 快捷翻译换掉输入框里的字，不打开翻译浮层

> 触发手势、输入法和监听线程的部分已由 0024 取代：现在是连按三下空格，不再判断组字。

快捷翻译是另一条路，不经过划词，也不打开翻译浮层。其他应用里焦点所在的输入框，连按两下空格，就把读到的那一段换成一家供应商的译文。有划选用划选，没有就用整段。两处都读不到时先全选再读。还是读不到，输入框保持原样。密码框不动。

默认供应商在设置里选，名单是当前打开的翻译服务，第一项是「自动（第一个可用）」。指定的那家后来关了或不能用，就用打开名单里的第一家。一家都没有，就不换。

连按两下空格是默认快捷键，可以改成带修饰键的组合，改了之后按一下就触发。输入法还在组字时，用来上屏的那下空格不算。上屏之后要再按两下。按住不放也不算。我们自己的窗口里，空格还是空格。

没有划选时，第一下空格照常进输入框，第二下才触发，译的是按下之前的整段。有划选时，第一下先不放进去，免得划选被一个空格冲掉；第二下没来，再把这一格空格补上。译文回来时，这段如果已经不是刚才读到的，就不盖。翻译失败，或遮盖自己出错，原文留着。快捷翻译命中遮盖时不确认，占位符照发，结果回来再填回。

换成功才进历史，取得方式是快捷翻译，并记下当时的来源应用。

设置的权限页同样列出「输入监视」，用系统的听键盘权限显示已授权或未授权。未授权时「去授权」打开系统设置并贴横幅。
译文写回输入框时，以这一段的选区替换为准。直接改整个值只有读回来确实是译文才算成功。读不回来，或选区没变成译文，就沿用划选；整段则再全选一次。用复制确认还是刚才那一段（多出来的一两格手势空格不算改过），再粘贴。粘贴之后不再要求辅助功能把译文读回来，很多输入框会假装写上了，或者根本读不到新文字。对不上就不盖。
微信输入法比普通应用更早拿到空格。监听放在键盘刚进入系统的那一层，才能数到用户按下的两下。输入法还在组字时，空格照旧上屏，不计入这两下。
两下之间的间隔从第一下按下时算，跟系统的双击速度走，至少 0.6 秒。只给 0.35 秒时，正常速度的连按会被当成两次单击。
连按两下空格要听键盘。系统设置的「输入监视」没允许本应用时，这个监听装不上，两下空格会照常打进输入框，译文不会出现。允许之后需要重新打开一次。

手势回调里不读输入框。对方应用要等这下空格送回去，才答得上辅助功能；在回调里问，问询会超时，这一下被当成没有输入框，连按两下就没有反应。回调只记下时间并决定吞不吞。问输入框放在回调返回之后。没有划选时，问完立刻把吞下的那一格补回去，不等第二下，所以正常打一个空格不会被拖住。


## 考虑过

- 打开翻译浮层再让人复制。要的是输入框里直接变成译文。
- 走写回。写回只盖划词时对得上的那句选区，而且要先有一次划词。
- 输入法上屏的那下空格算进两下里。上屏之后紧接着再按一下就会把整段换掉。
- 任何空格都先吞掉再等第二下。没有划选时，正常打一个空格会被拖住。
- 在事件回调里读输入框。问询超时，连按两下没有反应。
- 快捷翻译也先弹确认。这条路本身就不弹翻译浮层。
- 不进历史。换完之后原文只留在历史里，输入框里已经是译文。
