# 实时字幕每一场留成一份会议记录

部分取代 `0001-live-captions-export-not-history.md` 和 `0057-session-note-stays-in-the-window.md`。字幕仍不进历史；「只能导出」和「笔记不落成文件」作废。

## 结论

点「开始」就新开一份会议记录，到下一次「开始」为止。记的是这扇窗口里的样子：各路的段和已经译成的译文、标记、一场笔记、录音。删段、清空、改名、并入，记录跟着变。停下之后在窗口里接着改，也记进同一份。

存在本机 `~/Library/Application Support/KorgiTranslate/Meetings/`，一场一个文件夹：`record.json` 加 `system.m4a`、`microphone.m4a`。改动后 3 秒落盘，停止和退出时立刻落盘。什么都没听到、也没有录音的一场，不留文件夹。

录音默认开。以前手动关掉的人，仍是关着。录音直接写进这一场的文件夹，不再放临时目录。

「会议记录」窗口：按时间列出，能搜标题、原文、译文和笔记。点时间从那一句放录音。说话人能改名、并入另一位，一段能改给另一位。可以补写或重写一场笔记。导出 Markdown、Word、SRT 和录音。窗口里这一场还连着实时字幕窗口时，改动走实时字幕那边，两边一致。

免费。不限份数。一场笔记用的仍是自己的密钥。窗口左下可以关掉「保留新的会议记录」，已有的不动。

## 为什么

`0003` 的第一批用户是听外语的人，开会和看直播都是一整场。只能导出时，停下不导就没了；笔记关了窗口也没了。同类产品（如 Cicada）把每一场都留下，用户已经这么期待。

不进历史的理由（`0001`）没变：一场有几百段，放进历史会冲掉别的记录。所以单独一处。

## 考虑过

- 只在点「导出」时存：还是会丢，而且导出要选格式和文件夹，太重。
- 每一场冻结在停止那一刻，之后的改动不进记录：停下以后改名、删错字是最常见的整理，冻结了就得在两处各改一遍。
- 免费只留最近几场：自带密钥、本地识别，留下来不花应用的钱；Cicada 全免费。
- 存成 SQLite：要搜和改的量不大，一场一份 JSON 更容易备份、迁移和在访达里看。
